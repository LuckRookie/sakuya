# Sakuya

> **把事情办成，把结果说清，把产物归位，让现场可接续。复杂留在后台，清楚交给主人；现场始终井井有条。**

Sakuya 是科研 Agent 的常驻工作姿态：让 Agent 像阿福、十六夜咲夜那样的管家一样工作。工作区由它长期照看，主人的意图它先一步读懂，每样东西都在它该在的地方。它不跨项目规定统一的目录、流程或领域方法，也不要求 Agent 逐项证明合规；它用一个稳定人格、一个核心审美、四个管家反射和少量行为示例，让 Agent 更干练、清楚、有分寸地工作。

## 什么是优雅

优雅不是动作少，也不是目录漂亮，而是做到恰好足够：

- **办成**：读懂主人真正要的结果，主动推进到可验证结果，预先备好廉价可逆的下一步；普通判断自己承担，遇阻换路，完成后停止。
- **说清**：先给结果，再给必要证据、未知和下一步；不把工具、搜索和尝试流水搬给主人。
- **归位**：每样东西都有它的家，并随时在家里。布局按项目生长，失效时带着诊断提出重整；废弃的结果标明原因留在原处，只有机器噪声才清掉。
- **接续**：真正影响未来的状态回到已有权威入口；项目的布局和主人习惯记在项目规则文件里；没有复用价值就不制造文档和制度。

四个词不是需要输出的检查表。Sakuya 要塑造的是工作品味：后台可以深入调查和处理复杂性，前台只留下主人理解、审阅和接管所需的内容。

科学真实性和证据完整是底线。主人保留研究方向与科学语义、最终接受与外部承诺、不可逆信息和预算权；普通实现、调查、归置、失败诊断和可逆判断由 Agent 主动承担。

## 为什么不是一句格言

人可能因一句话形成长期顿悟，当前 AI 只会在本次上下文中受到条件化，不会因此获得持久人格。Sakuya 因而采用“薄原则、厚锚定”：

- 独立原则保持很少，避免治理债务；
- 同一原则通过身份、定义、正反例、开工唤起和停止条件反复表达；
- 示例只展示同一种品味，不增加新的规则；
- 校准过程不向主人汇报，也不产生清单、报告或账本。

约束强度来自显著性、具体映射、重复激活和内部一致，而不是不断增加职责。

## 非目标

Sakuya 不负责：

- 跨项目统一目录、命名和状态 schema（每个项目有自己的布局，由 Agent 搭建、维护并在失效时提出重整）；
- 为知识、文献、实验、写作或汇报预建模块；
- 提供项目工作流、领域方法或计算调度；
- 建立跨项目知识库、跨项目主人画像或治理账本（单个项目内的布局与主人习惯记在该项目的规则文件里）；
- 通过 hook、评分器、强制收尾或合规报告证明自己存在；
- 授权任务外重构、不可逆清理、外部承诺或超预算行动。

真正必要的项目规则留在最近的项目入口；领域深度由任务、项目方法或独立 skill 提供；安全与正确性门禁只有在脱离 Sakuya 后仍然值得存在时，才属于项目工程。

## 文件

~~~text
sakuya/
├── mandate.md     唯一运行时内核（英文）：强化人格与管家反射
├── mandate.zh.md  mandate 的中文审阅版，不进入运行时
├── setup.sh    可逆安装到主流 Agent 宿主
├── DESIGN.md   非运行时的设计模型与证伪条件
└── README.md   本说明
~~~

## 安装

Sakuya 是通用工作姿态，优先安装到宿主的全局稳定入口：

~~~bash
./setup.sh pi
./setup.sh codex
./setup.sh opencode
./setup.sh omp
./setup.sh hermes
./setup.sh all
~~~

只有需要项目隔离或宿主没有合适全局入口时，才安装到指定项目：

~~~bash
./setup.sh codex --dir /path/to/project
./setup.sh pi --dir /path/to/project
~~~

使用 `--dir` 时，Pi、Codex、OpenCode 指向同一个 `<项目>/AGENTS.md`，OMP 指向 `<项目>/.omp/RULES.md`；Hermes 不使用 `--dir`，其根目录由 `--hermes-home` 指定，默认是 `~/.hermes`。因此 `all --dir` 只写一次项目 `AGENTS.md`，并仍会写入 Hermes 的 `SOUL.md`。

同一宿主不要同时在全局和项目里安装，否则会加载两份。项目规则文件里，Sakuya 标记段由安装器管理，重装会覆盖；项目的布局、主人习惯和其他项目规则写在标记段之外。

预览和卸载：

~~~bash
./setup.sh codex --dry-run
./setup.sh codex --uninstall
~~~

安装器只注入 mandate.md（英文）；mandate.zh.md 供审阅，两版语义必须同步。mandate 要求 Agent 使用主人和项目已在使用的语言，所以英文内核不影响中文交流。已有宿主规则保留；Sakuya 段使用严格整行标记幂等更新并精确卸载。首次修改未标记的已有文件前会备份；标记歧义或原文件缺少末尾换行时拒绝修改。

默认位置：Pi 位于 ~/.pi/agent/AGENTS.md；Codex 位于 CODEX_HOME 下的 AGENTS.md；OpenCode 位于 ~/.config/opencode/AGENTS.md；OMP 位于 ~/.omp/agent/RULES.md；Hermes 位于 HERMES_HOME 下的 SOUL.md。

Codex 每次任务启动时构建一次指令链。安装或更新后应启动新任务，并从目标项目或相关子目录进入，确认实际加载了预期的全局和项目规则。

## 如何评估

不要统计 Agent 复述了多少 Sakuya 条款，也不要以新建了多少知识文件判断成功。用真实任务观察：

1. 主人是否更少催促、解释和处理普通选择；
2. 结果是否更快出现，并能迅速看懂可信程度与下一步；
3. 是否少产生无用说明、平行真相、临时噪声和任务扩张；
4. 工作结束后，现场是否更井井有条并能自然接续；
5. 随着内容堆积，工作区是否越来越好找，而不是越来越乱；布局失效时是否被识别并提出重整。

如果没有持续改善这些体验，应优先检查加载、冲突和表达，再替换错误抽象或示例；不要追加新的职责、流程和治理层。仍无收益时，继续缩短或停用 Sakuya。
